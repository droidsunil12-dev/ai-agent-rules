### Always responsive for mobile screens (HARD, 2026-11-19, user-enforced)
- **All screens must be responsive for mobile viewports (375-430px width).** Never ship a layout that breaks on mobile.
- **Banner text & asset distribution:** when a banner has graphic art on one side + content on the other, reserve 35-45% width for the artwork and 55-65% for the text/CTA corridor so text never wraps or overflows. - **Universal Banner Contrast & Alignment Rule (HARD, 2026-11-19, user-enforced):**
  - **Universal applicability:** Applies to ANY industry, screen type, or orientation (fintech, SaaS, e-commerce, media, healthcare, etc.).
  - **Banner natural negative space — NO ugly gradient overlays or white haze:** Intentional empty space for text and buttons means keeping graphic elements strictly on ONE side (35-45%) and leaving the other side (55-65%) as clean, natural negative space of the scene itself (same continuous studio lighting, seamless backdrop material, depth). NEVER place or prompt an ugly gradient overlay, white haze, or misty fade across the banner (neither baked into the image generation prompt nor in CSS). Empty space is the clean scene backdrop itself, not an artificial white spray/wash. In image prompt avoid array: add `"gradient overlay", "white haze", "faded wash", "misty fog", "airbrushed patch", "two-tone background split"`.
  - **Sample backdrop pixel luminance in empty space:** Text, numbers, labels, badges, and CTA buttons MUST derive their color from actual background pixel luminance of the banner's empty/negative space ($L = 0.2126 \cdot (R/255) + 0.7152 \cdot (G/255) + 0.0722 \cdot (B/255)$).
  - **Light backdrop (luminance > 0.5) → DARK text:** If empty space is light (white, cream, pastel tints), use dark text matching the project's darkest brand tone or neutral-900 (e.g. `var(--color-text-primary)`, `#0F172A`, `#111827`, `#0F2E24`) with high contrast. CTA button solid dark with white text or dark border.
  - **Dark backdrop (luminance <= 0.5) → LIGHT text:** If empty space is dark (deep tones, navy, black), use white/light text (`#FFFFFF`, `#F8FAFC`, `var(--color-text-inverse)`). CTA button light/accent.
  - **NEVER use overlays, gradient masks, or solid patches over banners:** NEVER apply `linear-gradient(...)` dark patches, semi-transparent overlays, or solid backdrop boxes over a banner card to force contrast. It corrupts the art and creates ugly seams. Adapt typography to the asset; never patch the asset to fit typography.
  - **NEVER use text-shadow halos:** Remove dirty white or dark blurry halos (`text-shadow: none`).
  - **Single-Stack Unified Container for alignment:** Do NOT separate title/stat text and CTA button into independent containers or absolute positions. Group label/eyebrow, title/metric, badge/meta, and CTA button inside ONE single flex container (`display: flex; flex-direction: column; align-items: [flex-end | flex-start]; gap: 8px;`) on the empty side. ### Tool Conventions
- **PowerShell via bash tool:** inline `$vars` get mangled by the outer shell before PowerShell parses them. Write to a `.ps1` file via `write_file` + run with `powershell -NoProfile -File <path>`; only variable-free one-liners are safe inline. Multi-line `-Command` bodies with a leading-dash line at column 0 (e.g. `--- verifying ---`) throw `ParserError: Missing expression after unary operator '-'` — use `#` comments or a `.ps1` file instead.
- **REPL `fetch()` vs `webfetch`:** in routine/keep-alive agent runs, REPL `fetch()` can fail with "Tab … is no longer available" (stale/detached background tab). The dedicated `webfetch` tool reliably reads public URLs. Single-line no-variable PowerShell commands via bash are a reliable fallback when both are unavailable.
- **Account-filesystem tool split:** bash/PowerShell and `read_file`/`write_file` can have different views of `.aside/u/0/`. A file that ENOENTs through `read_file` may still be writable via `write_file` and immediately readable after. When this happens, reconstruct from the first successful read and persist via `write_file`; do NOT fall back to bash to inspect.
- **GUI installer in headless context:** use the vendor's true silent switch (Inno: `/VERYSILENT /SILENT /NORESTART /SUPPRESSMSGBOXES /S`) AND wrap with `$p.WaitForExit(ms); if(-not $ok){$p.Kill()}` inside try/catch `exit 0` — never a bare `Start-Process -Wait`.
- **GitHub Actions YAML `run:|` PowerShell:** keep `-replace` subexpressions simple (no trailing pipeline inside parens); here-strings (`@"..."@`) break YAML parsing — use PS array + `Set-Content`; PS7 hash-literal with interpolated `$` values throws `ParserError` — build headers by index assignment (`$h["Authorization"] = "token " + $envPAT`), not literal syntax.
- **PowerShell `Select-String` + 1-based indexing:** `($lines | Select-String -Pattern X).LineNumber - 1` returns `$null - 1 = -1` when there is no match; `$lines[-1]` indexes the **last** element. Always guard with `if ($m = ...)` before indexing.
