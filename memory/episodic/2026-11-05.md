## 22:20 Credwise coverage marquee: seamless-loop diagnosis + fix
Reference: sessions.get("8fF8Jia1Xo0knSvJ")
Credwise home has a navy "product families" marquee (`index.html` `section.cov` / `#cov-track`: two identical `.cov-group` copies, `gap:32px; padding-right:32px`, `@keyframes marquee-right` translating -50%→0 over 28s). Client reported the loop "not seamlessly stitched — I can see the end." Diagnosis: it was already geometrically seamless (track width = exactly 2× one group; internal gap == seam gap == 32px; the two wrap frames translateX(0) vs -50% are pixel-identical, ~0.56/255 avg delta with only a ~1px sub-pixel AA pop). The real culprit was `loading="lazy"` on the FIRST group's 9 icons — lazy images in a moving strip pop in late so one half renders differently at the seam — compounded by no GPU compositing on the track.
Fix (applied to root AND netlify-upload per the two-tree sync rule): removed `loading="lazy"` from the 9 `.coverage-icon` imgs in group1 (group2 already had none) and added `will-change:transform` to `.cov-track`. Scope the lazy removal to lines containing `class="coverage-icon"` (PowerShell line-by-line `.Replace`) because index.html holds ~22 `loading="lazy"` imgs total and only 9 are the marquee ones — a global replace would wrongly un-lazy the about/hero images.
Reusable animation/marquee QA technique: extract just the component into a throwaway `_test.html` served by the local `http.server` (removes the sticky-header + scroll-reveal interference that mangles `element.screenshot()` of that strip), then in-page capture the two wrap frames and consecutive running frames, stack them, and pixel-diff via `canvas.getImageData`. Hide `header,nav` before element shots; remember to delete the harness and terminate the server session when done.
