- **Launch:** `& 'C:\Users\Doraemon\.aside\runtime\python\runtime\python.exe' -W ignore main.py` with cwd = app dir. The WindowsApps `python3.13.exe` path also works interactively.
- **Audio driver issue (WDM-KS):** All WDM-KS audio input devices on this PC fail with `PaErrorCode -9999: Blocking API not supported` (broken Windows audio driver, not a code bug). WASAPI and MME backends also expose 0 input channels. Both `sounddevice` and `pyaudio` (same PortAudio backend) hit the same error; `soundcard` (pure WASAPI/COM) also finds 0 real mics. TTS/output is also broken by the same driver issue.
- **Patch applied to `main.py` `_listen_audio`:** when both the chosen mic device AND the system default fail to open, the code now logs "Microphone unavailable … voice input disabled" and enters a keep-alive `while True: await asyncio.sleep(1)` instead of re-raising, so the TaskGroup never unwinds and the JARVIS UI window stays up. Same treatment on the outer `except` block. TTS/speaker fallback for `_play_audio` (also broken) is not yet patched — upgrade path: apply the same graceful-disable pattern when output becomes a blocker.
- **App status post-patch:** window "JARVIS — MARK LVI" visible, text input works, voice-in off (mic unavailable), PID confirmed at launch. SYS MONITOR reports "AI CORE ACTIVE", "SEC CLEARED", "PROTOCOL LVI", uptime + process count.
- **First-boot init:** JARVIS requires a **Gemini API key** (pasted via the clipboard-detected panel or the GEMINI API KEY field) and an OS selection (auto-detected Windows) before first boot. Without the key the app sits at "INITIALISATION REQUIRED" and does not come online.
- **Auto-start + wake word:** JARVIS's SETUP panel shows **AUTO-START: ON** and installs **openwakeword** at boot (SYS log: "wake word installing openwakeword"). The app auto-starts with the OS session and registers a wake word for voice activation.
- **Auto-mute behavior:** JARVIS auto-mutes its own microphone when a background audio source (e.g. a video) is playing with sound. The log shows `SYS: Microphone muted. The video's sound is on — silence it, close it, or press F4 to talk.` So "JARVIS can't listen" can mean **muted-by-design**, not a device failure. Unmute via the bottom-right **MICROPHONE MUTED** button or key **F4**; close/silence the competing audio source.
- **Audio device list for this PC** (`sounddevice` 0.5.6, PortAudio/WASAPI): working input = dev 1 `Headset (Crusher Wireless)` (default input `[1, 3]`), opens fine at JARVIS's exact params (16000 Hz / 1 ch / int16 / 1024 blocksize). Broken inputs = Realtek HDA mics dev 19/18/20 → `PaErrorCode -9999`. `config/api_keys.json` has no saved `input_device`/`output_device`, so JARVIS resolves to the PortAudio system default.
- **Hindi voice confirmed working:** user asked JARVIS to "speak in Hindi only" and it complied (responded in Hindi/Bhojpuri, warned about RAM in Hindi). YouTube song control also works (user requested Hindi + English songs; JARVIS searched and played them).
- **Log-capture gotcha:** `python main.py 2>&1 > log.txt` only captures ffmpeg's stderr (MFT/AV1 hardware-decoder noise), NOT the app's own `[JARVIS]` print lines. To read JARVIS's real log panel, screenshot the window (`pygetwindow` activate + `PIL.ImageGrab.grab` on the window bbox) instead of redirecting stdout.
- **Reliable (re)start:** `& 'C:\Users\Doraemon\.aside\runtime\python\runtime\python.exe' -W ignore main.py` (cwd = app dir). Verify alive via `psutil.process_iter` grepping `cmdline` for `main.py` (not `-c`); window title is `JARVIS — MARK LVI`.
