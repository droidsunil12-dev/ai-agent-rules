## Current
- Web file editor is **CodeMirror 6**: there is NO `<textarea>`; the editable surface is `.cm-editor .cm-content` (contenteditable). To inject multi-line content programmatically: `const dt = new DataTransfer(); dt.setData('text/plain', text);` then dispatch `new ClipboardEvent('paste', {bubbles:true, cancelable:true, clipboardData: dt})` on `.cm-content`. Confirm via accessibility snapshot before committing.
- Navigating the "Name your file..." field: typing a full slash path (e.g. `.github/workflows/rdp.yml`) makes GitHub treat the last segment as a directory. To target a nested path, navigate the tab to `/new/main/<directory>` first (URL sets the target dir; page title becomes "New File at <path>"), then fill ONLY the leaf filename.
- Some GitHub controls render in **shadow DOM** (e.g. the "Enable Actions" button): visible in Playwright's accessibility snapshot (with a ref) but not found by `document.querySelectorAll` inside `page.evaluate`. Use Playwright ref-based locators (which pierce shadow DOM); read attributes one at a time via `page.locator(ref).getAttribute(...)`.
- `api.github.com` rejects the browser session cookie (401 "Bad credentials") — it needs a Bearer/PAT. The token-free path to create/commit files is the **web UI**: open `/new/main/<dir>`, inject content into CodeMirror, click Commit.
- Token creation (`/settings/tokens/new`) hits a sudo-mode email-OTP gate (`#sudo_email_otp`); the 6-digit code must come from the user. **2026-11-16 refinement:** the "Generate new token" button first opens a submenu: pick "Generate new token (classic)" (vs fine-grained). After the user passes the sudo gate, the classic-token form appears. `tfcsunil53-cloud` already has a classic PAT `rdp-cloud-pc-runner` (scopes `repo, workflow`, expiring Dec 7 2026). New PAT `client-work-runner` (scopes `repo + workflow`, No expiration) created 2026-11-16, wired to `git` (token embedded in clone remote URL) + `GH_TOKEN` env var + `gh` CLI.
- Committing a valid `.github/workflows/` file does NOT enable Actions on a fresh account; the "Enable Actions" button is a broken link (`/actions/enable` → 404). Unblock via PAT + API.
- To read committed file content without a token: fetch the web diff endpoint `/<owner>/<repo>/commit/<sha>.diff` (200, plain text); its `+++ b/<path>` line reveals the true committed path.
- GitHub Actions workflow-dispatch POST: empty body → 422 (`"ref" wasn't supplied`). Must include `{ref: "<default_branch>"}`; read `default_branch` via `GET /repos/<owner>/<repo>` first.
- `GET /repos/<owner>/<repo>/actions/runs?per_page=N` returns `{"total_count":N, "workflow_runs":[...]}`, NOT a bare array.
- GitHub Actions job log blobs (`GET /repos/<owner>/<repo>/actions/runs/<runId>/logs`) return **404** while any step in the job is still `in_progress` — the logs are not finalised until the job completes. A keep-alive infinite-loop step (`while($true){ Sleep }`) blocks log finalisation indefinitely, so the logs for that run will 404 until the run is force-cancelled at its timeout.
- `GITHUB_TOKEN` auto-injected into a workflow job is **read-only** on public repos — `PUT .../contents/...` with it returns **401 Bad credentials**. Use a user PAT for any repo write from inside a workflow. The token must be wired into the job's `env:` block or the step sees `$null`.
- Hardcoded PATs in committed workflow YAML get blocked by GitHub **Push Protection** (secret-scanning rule GH013) — the push is rejected until the secret is removed from the commit or unblocked at the repo's secret-scanning URL. Always reference secrets (e.g. `${{ secrets.X }}`), never inline the token in the file.
- GitHub delete-repo (Settings → Danger Zone) on a recently-active account **may** trigger a sudo-mode email-verify gate ("Confirm access" + 6-digit email code), but it is **conditional, not a hard requirement**: observed triggering at 13:58 on 2026-11-07 but NOT triggering again at 14:14 (same session). The gate is per-account sudo, valid for hours after one re-auth. Plan GitHub delete/transfer/billing ops expecting *possibly* a gate; don't assume one.
- **History-erase technique:** to remove all commits mentioning a secret, `git checkout --orphan clean-history` → `git add` only the desired current files → `git commit` → `git push --force origin clean-history:main`. The `:main` target syntax is what overwrites the default branch; `--force` pushes to the new branch name first. Note: `git-filter-repo --replace-text` must reference a **file** containing `old==>new` mappings (inline string form is treated as a filename and fails with `OSError: Invalid argument`).
- **Local artifact cleanup gotcha:** `Remove-Item -Recurse -Force` on a folder fails ("The process cannot access the file") when the PowerShell tool's own cwd is parked inside the target. `cd` out of the target root first; killing `git` procs alone does not unblock it — the shell's working directory is the file holder.
- `POST .../actions/workflows/<id>/dispatches` can return **422** transiently even when the workflow YAML clearly has `on: workflow_dispatch:` — this is a transient API hiccup. Retry once or check if the dispatch actually queued (the run may appear in `GET .../actions/runs` despite the 422).
- PowerShell `@"..."@` here-strings inside a GitHub Actions `run: |` YAML block (pwsh) break because the YAML block-scanner mis-handles the leading-space `"` and the closing `"@`. Safer pattern: a PS array `@('line1','line2','line3')` piped to `Set-Content` — no here-string needed.
