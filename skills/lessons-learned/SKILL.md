# Lessons Learned (recurring mistakes → corrections)

Each entry: what went wrong, then the rule to prevent it. Follow the rule; do not re-derive the mistake.

- **Mistake.** Banner text cramped on right side, currency symbol (₹) broke to separate line from amount, "+12% vs last month" wrapped to 3 lines on mobile viewport. **Rule.** Always use `white-space: nowrap` on critical text (currency + amount, percentages). Constrain banner graphic to 35% width on left side, leave 65% for text on right. Use `display: flex; align-items: baseline;` on amount container. Verify at 375px mobile viewport before deploying.

## Global: Never assume - verify first (applies to every task)
**Mistake.** Repeatedly assumed things were wrong (a real contact = "dummy placeholder", a fine layout = "broken", a value = "a bug") and acted on the assumption, when the truth was the opposite. The Vikash phone (`+91 98113 61364`) is the owner's **real** number - I flagged it as a shipped blunder without ever checking it was fake. **Rule (durable, user-enforced).** State it, verify it, then act - never assume. Before flagging or changing ANYTHING (content, data, layout, alignment, a suspected bug, a fix), confirm it against a known-good source: the client's own data, `client-work\projects.md`, the live site, or the owner. A real-looking value = real until proven otherwise. When in doubt, ASK the owner; do not silently change it. This beats any "it looks like X" intuition, and it overrides the content-sweep/layout-QA steps when those would turn on a guess.

- **Persistent top-level scope.** `const`/`let` persist across every REPL call in the session. Reusing an identifier that was already declared throws `Identifier 'x' has already been declared`. Use fresh, uniquely-prefixed variable names per call (e.g. `cwFullUrl`, `depRefZ`, `s111`). When you hit this error, it is a name collision, not a logic bug — rename and re-run.
- **`return` does not surface values.** REPL output only shows `console.log(...)`. Always `console.log` the data you need back. Returning an object/array shows nothing.
- **Don't `slice` snapshot objects.** `snapshot()` returns `{tree, diff}` (or a string). `s1.slice(0,n)` throws `slice is not a function`. Print `s.tree` or `s.diff`, or the string directly. Never `tree.slice()` — it hides context.
- **`fetch()` can fail with "Tab … is no longer available."** Stale/detached background tabs break REPL `fetch()`. For public URLs use the dedicated `webfetch` tool; it is reliable in long/keep-alive runs.
- **`display()` needs image bytes.** Pass a Buffer/Uint8Array or a base64/data-URL string, not arbitrary text.

## Building / shipping a ZIP deliverable

- **Never let a prior deliverable ZIP get bundled into the new one.** `Compress-Archive -Path "$pub\*"` silently includes an old `<name>.zip` sitting in the same folder, doubling the size and shipping junk. Stage a clean copy first, excluding `*.zip` (and `node_modules`, `.git`), then compress the staged folder. Verify by reading back the ZIP's entries for the nested old ZIP before declaring done.
- **PowerShell gotchas (bash tool).** Inline `$vars` get mangled by the outer shell — write a `.ps1` via `write_file`, then `powershell -NoProfile -File <path>`; only variable-free one-liners are safe inline. A multi-line `-Command` whose first line starts with a dash at column 0 (e.g. `--- verifying ---`) throws `ParserError`. A trailing `Get-Member -InputObject $null` line errors; just remove it.
- **Verify the deliverable, don't assume it.** After building, extract and grep for the wired content (endpoint URL, real vs demo copy) to confirm the ZIP contains what you think.

## Wiring a site form to a Google Apps Script endpoint

- **CORS: post `text/plain`, not `application/json`.** A browser `fetch` POST to a Google Web App with `Content-Type: application/json` triggers a CORS preflight that Apps Script fails. Use `Content-Type: text/plain;charset=utf-8` and put the JSON in the body; the `doPost` handler parses `e.postData.contents` as JSON.
- **Apps Script auto-coerces numbers and `+` strings.** Storing a phone like `+91 9123456789` in a default cell makes Sheets read it as a formula/number (`#ERROR!` or a mangled value). In the `doPost` handler, set the phone column's number format to `@` (text) **before** `setValue(String(phone))`. Verify with a CSV export, not just `readSheet` (the numeric-render view can mislead).
- **No build step on a static site = edit source + sync publish tree.** For two-tree client sites, edit the source tree, then copy the changed files into the publish tree so the ZIP (built from publish) actually ships the change. Confirm the publish tree has the endpoint and that demo copy is gone.
- **New code change = new deployment version = new `/exec` URL.** If you edit the `doPost`, create a new version; the old `/exec` URL keeps pointing at the old code. Update the client-side `ENQUIRY_ENDPOINT` to the new URL and redeploy the site, or the live form still posts to the old script.

## Google OAuth consent / Apps Script deploy in the browser

- **Consent popups open user-owned tabs you cannot attach.** The "Authorize access" button opens a `accounts.google.com/signin/oauth/warning` popup. `attachBrowserTab(id)` on it fails ("No open browser tab found for targetId"). Instead: read the popup URL from `listBrowserTabs()` and `openTab(thatUrl)` in an **agent** tab, then drive the consent flow there.
- **Consent flow shape (unverified app):** warning page → click **Advanced** → click **"Go to <app> (unsafe)"** → consent screen → tick **Select all** scopes → **Continue** → "successfully authorized" callback. The "You did not allow any access" sub-dialog means you hit Continue with scopes collapsed — click **Go back**, tick Select all, then Continue.
- **Deploy keeps resetting if OAuth interrupts it.** After the consent callback, the deploy dialog reopens at "requires you to authorize". Go back to the Apps Script editor, click **Deploy → Manage deployments**, do **Create deployment → Web app → Anyone → Deploy** once more cleanly. Then read the full Web app URL from the link's DOM `href` (the dialog text truncates it) via `page.evaluate`.
- **`attachActiveBrowserTab()` grabs whatever tab is active, not the one you want.** After a `googleSheets.connect()` it may point at a sheet. Check `page.url()` before acting on "the active tab".

## User-owned vs agent tabs

- **You cannot attach user-owned tabs outside the agent group.** `listBrowserTabs()` sees them (you can read their URL), but `attachBrowserTab(targetId)` throws "No open browser tab found for targetId". This blocks driving that tab (e.g. sending a file to WhatsApp from a user-opened WhatsApp tab).
- **When blocked on a user tab, do not spin.** State it is blocked, give the one action that unblocks it (focus that tab / do the step manually), and move on. The handover-when-stuck skill covers the hold-and-monitor behavior.

## Banner design & negative space (2026-11-19, user-enforced)
**Mistake (ugly gradient overlays on banners).** Prompted or accepted banner assets where an artificial white gradient haze/mist was faded across the right half of the banner image to create "empty space" for text and buttons. This made banners look ugly, cheap, and destroyed the 3D scene depth.
